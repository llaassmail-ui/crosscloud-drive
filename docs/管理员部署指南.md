# 跨域云盘 V2 管理员部署指南

本指南面向负责阿里云国际版 OSS、RAM 和 Windows 云电脑的管理员。跨域云盘通过 rclone 和 WinFsp，将一个 OSS Bucket 或其中的对象前缀挂载为 Windows 盘符。

V2 首期只支持阿里云国际版 OSS。每个 Windows 用户由本工具管理一个连接；工具不会接管其他 Windows 用户、其他软件或手工启动的非目标 rclone 进程。

## 1. 推荐架构

普通员工建议共用一个私有 Bucket，并按用户划分前缀：

```text
<bucket-name>/
  users/
    <user-a>/
    <user-b>/
  shared/
```

推荐原则：

- Bucket ACL 设为私有并阻止公共访问。
- 每位员工使用独立 RAM 用户和独立 AccessKey。
- 普通员工只获得自己前缀的对象权限。
- 管理员或 NAS 账号才获得整个 Bucket 的对象读写权限。
- 不使用阿里云主账号 AccessKey。
- 云电脑和 OSS 尽量位于同一地域，并验证所用 Endpoint 的网络和计费路径。

## 2. OSS 配置

### 2.1 服务端加密

可以启用 OSS 完全托管密钥（SSE-OSS/AES256）。对象写入后由 OSS 加密保存，读取时由 OSS 自动解密；用户通过挂载打开或正常下载时得到原始文件内容，而不是不可读的密文。

服务端加密保护 OSS 介质上的静态数据，不能替代 RAM 最小权限、HTTPS、终端防护或客户端自行加密。

### 2.2 版本控制和生命周期

需要误删恢复时可以开启版本控制，但删除和覆盖后的历史版本会继续占用存储空间。建议同时配置生命周期规则：

- 历史版本保留 30 或 60 天后删除。
- 清理过期删除标记。
- 未完成的分片上传保留 7 天后清理。

OSS 的“文件夹”本质上是对象名前缀。空文件夹可能表现为 0 字节目录标记；这与 NTFS 目录不同。

## 3. RAM 权限

### 3.1 普通用户前缀策略

以下策略允许 RAM 用户列出并读写 `<bucket-name>/users/<user>/`，不能访问其他前缀：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetBucketLocation",
        "oss:ListObjects",
        "oss:ListObjectsV2"
      ],
      "Resource": "acs:oss:*:*:<bucket-name>",
      "Condition": {
        "StringLike": {
          "oss:Prefix": [
            "users/<user>/",
            "users/<user>/*"
          ]
        }
      }
    },
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetObject",
        "oss:PutObject",
        "oss:DeleteObject",
        "oss:AbortMultipartUpload",
        "oss:ListParts",
        "oss:RestoreObject"
      ],
      "Resource": "acs:oss:*:*:<bucket-name>/users/<user>/*"
    }
  ]
}
```

第一段允许列出 Bucket，但通过 `oss:Prefix` 把可见范围限制到用户目录。第二段允许用户在该前缀中读取、上传、覆盖、删除、恢复归档对象和处理分片上传。

### 3.2 管理员或 NAS 全桶对象策略

以下策略允许访问整个 Bucket 的对象和版本。它不授予修改 Bucket ACL、加密、生命周期、跨域规则或删除 Bucket 等管理权限。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetBucketLocation",
        "oss:GetBucketInfo",
        "oss:GetBucketStat",
        "oss:ListObjects",
        "oss:ListObjectsV2",
        "oss:ListObjectVersions"
      ],
      "Resource": [
        "acs:oss:*:*:<bucket-name>"
      ]
    },
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetObject",
        "oss:PutObject",
        "oss:DeleteObject",
        "oss:DeleteObjectVersion",
        "oss:AbortMultipartUpload",
        "oss:ListParts",
        "oss:RestoreObject"
      ],
      "Resource": [
        "acs:oss:*:*:<bucket-name>/*"
      ]
    }
  ]
}
```

不要把全桶策略发给普通员工。若某个管理程序还需要配置 Bucket 属性，应单独建立管理策略，不要把这些权限混入日常挂载账号。

## 4. 使用 CLI 批量创建 RAM 用户

前提：

- 已安装 Alibaba Cloud CLI。
- 已通过 `aliyun configure` 配置管理员身份。
- 管理身份有 RAM 用户、策略绑定和 AccessKey 管理权限。
- 在项目根目录运行命令。

为多个用户创建独立前缀策略：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\create-oss-ram-users.ps1 `
    -Bucket "<bucket-name>" `
    -Usernames "<user-a>","<user-b>" `
    -CreateAccessKey
```

默认生成 `oss-<user>` RAM 用户、`oss-prefix-<user>` 策略和 `users/<user>` OSS 路径。

自定义根前缀：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\create-oss-ram-users.ps1 `
    -Bucket "<bucket-name>" `
    -PrefixRoot "staff" `
    -Usernames "<user-a>","<user-b>" `
    -CreateAccessKey
```

创建全桶对象访问账号：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\create-oss-ram-users.ps1 `
    -Bucket "<bucket-name>" `
    -Usernames "<admin-user>" `
    -PolicyMode FullBucket `
    -CreateAccessKey
```

使用 `-CreateAccessKey` 时，脚本会在当前目录生成 `oss-ram-users-accesskeys.csv`。其中包含明文 Secret：

- 立即移入受控密码管理器。
- 只通过安全渠道交付给对应用户。
- 配置完成后安全删除 CSV。
- 不要把 CSV、截图或 `rclone.conf` 提交到 Git。
- Secret 泄露时立即禁用旧 AccessKey 并创建新密钥。

## 5. GUI 部署

GUI 依赖 `scripts` 下的模块、Provider 和语言文件，因此必须分发完整项目目录，不能只分发一个 `.ps1`。

普通用户双击：

```text
scripts\start-oss-mount-gui.vbs
```

这个入口会隐藏 PowerShell 启动窗口。`start-oss-mount-gui.cmd` 仍然保留为兼容入口。

也可以从 PowerShell 启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\oss-mount-gui.ps1
```

界面分为：

- “连接”：查看状态、安装 rclone/WinFsp、打开盘符、停止或重新连接。
- “设置”：配置地域、Endpoint、Bucket、路径、凭据、盘符、缓存和自动恢复。
- “活动”：查看最近 500 条本地活动、打开日志目录和复制脱敏诊断。

Bucket 默认留空；远端目录默认显示 `/`，内部表示 Bucket 根目录。普通用户通常应填写 `/users/<user>`。

建议首次配置顺序：

1. 在“连接”页安装组件。
2. 在“设置”页填写连接信息。
3. 点击“仅测试”。
4. 测试成功后点击“保存并连接”。
5. 返回“连接”页确认盘符和状态。

GUI 使用 Windows PowerShell 5.1 和 WinForms，不需要 Python、Node.js、Go 或其他语言运行时。安装组件可能触发 UAC。

## 6. CLI 单机部署

CLI 与 GUI 调用同一套 Provider、状态、挂载和计划任务模块：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-oss-rclone-mount.ps1 `
    -Bucket "<bucket-name>" `
    -Region "ap-southeast-1" `
    -OssPath "users/<user>" `
    -DriveLetter "Z"
```

脚本会安全提示输入 RAM AccessKey ID 和 Secret。Secret 不应作为命令行参数传入。

已经安装 rclone 和 WinFsp 时：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-oss-rclone-mount.ps1 `
    -Bucket "<bucket-name>" `
    -OssPath "users/<user>" `
    -DriveLetter "Z" `
    -SkipInstall
```

挂载整个 Bucket 仅适用于绑定 FullBucket 策略的账号：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-oss-rclone-mount.ps1 `
    -Bucket "<bucket-name>" `
    -OssPath "/" `
    -DriveLetter "Z" `
    -SkipInstall
```

默认 remote 名为 `crosscloud-main`，默认缓存上限为 `5G`，目录缓存为 `1m`。缓存可通过 `-CacheMaxSize "10G"` 调整，最小为 `1G`。

## 7. 自动挂载和恢复

工具在当前 Windows 用户下创建两个隐藏任务：

```text
CrossCloud Drive - Sign-in mount
CrossCloud Drive - Recovery
```

- 登录任务在用户登录 Windows 后恢复挂载。
- 恢复任务每 5 分钟检查一次盘符和本工具管理的目标进程。
- 已有连接时不会启动第二个 rclone。
- 用户点击“停止”后，本次登录写入暂停标记，恢复任务不会重新拉起；下次登录恢复。
- 两个任务通过 `%LOCALAPPDATA%\CrossCloudDrive\runtime\MountWorker.vbs` 隐藏启动，正常情况下不会闪出命令行窗口。

若仍每 5 分钟出现窗口，检查是否残留旧版 `Mount OSS workspace drive ...` 任务。使用 GUI 的“移除本机连接”可清理本工具识别的 V1/V2 遗留任务。

## 8. 停止、移除与卸载

“停止”只终止本工具当前连接对应的挂载进程，保留 remote、状态、缓存和登录任务，并在本次登录暂停自动恢复。

“移除本机连接”会：

- 删除本工具 V1/V2 计划任务。
- 精确停止目标 rclone 挂载，不结束其他 rclone 进程。
- 清理盘符和 Windows 网络位置记录。
- 删除本工具管理的 rclone remote、状态、启动文件和默认缓存。
- 默认保留工具目录以外的自定义缓存。
- 在二次确认后选择性卸载 rclone 和 WinFsp。

停止、移除和依赖卸载都只处理本机，不删除 OSS 云端对象。需要清理云端历史版本时，应在 OSS 控制台通过版本管理和生命周期策略执行，并遵循企业审批流程。

## 9. 缓存与磁盘

默认缓存位于：

```text
%LOCALAPPDATA%\CrossCloudDrive\cache
```

默认上限 `5G`。`5G` 适合办公文档，`10G` 适合一般文件，`20G` 适合频繁处理大文件且磁盘空间充足的设备。自定义值至少为 `1G`。

`--vfs-cache-max-size` 是清理目标，不是严格磁盘配额。正在上传或被应用占用的文件可能让缓存短时间超过配置值。系统盘满时，可能出现保存失败、上传失败、反复重试或应用卡住。

## 10. 删除、版本控制和时间

用户从挂载盘删除文件时，rclone 会向 OSS 发送对象删除操作。OSS 控制台仍显示内容的常见原因：

- Bucket 开启了版本控制，旧版本或删除标记仍存在。
- 控制台正在显示历史版本。
- 目录标记对象仍存在。
- 目录缓存尚未刷新。
- 上传或删除因权限、网络、Endpoint 或磁盘问题失败。

不要向普通用户提供无范围限制的云端批量删除命令。历史版本和删除标记由管理员通过 OSS 生命周期统一治理。

OSS 服务端时间使用 UTC，Windows 文件资源管理器通常按本地时区显示。工具保留对象修改时间；不同界面的显示时区不同不代表文件内容被修改。

## 11. 费用治理

rclone 和 WinFsp 不收取 OSS 使用费。主要费用包括：

- 当前对象和历史版本的存储容量与存储时长。
- PUT、GET、LIST、DELETE 和分片上传等请求次数。
- OSS 到云电脑的公网、跨地域或特定网络路径流量。
- 未完成分片和版本控制保留内容的存储费用。

实际单价取决于地域、存储类型、网络路径和阿里云国际站当前价格。建议在费用中心设置预算与告警，验证 Endpoint 的实际网络路径，并为历史版本、删除标记和未完成分片配置生命周期规则。

## 12. 排障

### AccessDenied

检查 RAM 策略、AccessKey 所属用户、Bucket、Endpoint 和路径大小写。`users/<user>/` 与其他拼写是不同前缀。

### 盘符未出现

检查“活动”页和：

```text
%LOCALAPPDATA%\CrossCloudDrive\logs\mount.log
```

确认 rclone、WinFsp 已安装，盘符未被占用，系统盘有可用空间。

### 显示为网络位置

这是 rclone 网络模式的预期表现，不代表挂载失败。

### Secret 重新打开后为空

工具状态 JSON 不保存 Secret。Secret 由当前 Windows 用户的 rclone 配置管理。轮换 AccessKey 时重新输入 ID 和 Secret，再执行“保存并连接”。

## 13. 发布安全检查

公开发布前执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-ReleaseReadiness.ps1
```

该脚本会执行 PowerShell 语法检查、全部本地测试和公开发布敏感信息扫描。字段名、策略动作名和扫描规则本身不代表真实凭据；发现匹配结果后仍需人工核对上下文。

人工确认仓库不含真实凭据、凭据 CSV、`rclone.conf`、日志、缓存、真实 Bucket、员工姓名、公司内部路径或截图，也不包含结束全部 rclone 进程或直接批量删除云端对象的排障命令。
